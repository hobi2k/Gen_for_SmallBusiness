# 소상공인용 광고 콘텐츠 제작 플랫폼 구현 기획서

## 1. 목표
이 프로젝트는 소상공인이 상품 정보와 이미지만 넣어도 광고에 바로 쓸 수 있는 결과물을 빠르게 만드는 서비스를 구현하는 것을 목표로 합니다.

지금 제품 구조는 이렇게 고정합니다.
- 메인 진입점은 채팅
- 세부 제어가 필요할 때만 전용 생성 화면 사용
- 생성 종류는 세 가지로 분리
  - 이미지 생성
  - 영상 생성
  - 음악 생성
- 실제 로컬 모델 경로에서 이미지, 영상, 음악, 합성본까지 끝까지 생성돼야 함
- 규칙 기반 분기와 폴백 결과물은 사용하지 않음

## 2. 현재 입력

### 공통 입력
- 상품명
- 프롬프트
- 톤
- 영상 길이 `1~40초`

### 이미지 생성
- 참고 이미지 업로드 가능
- 가로 배너 크기 입력 가능
- 세로 상세 이미지 크기 입력 가능
- 업로드 이미지가 있으면 광고 포스터형 `img2img`
- 업로드 이미지가 없으면 광고 포스터형 `text-to-image`
- 영어 라벨은 모델이 만들 수 있게 두고, 한국어 카피는 후처리 오버레이로 넣음

### 영상 생성
- 참고 이미지 업로드 가능
- 음악 포함 여부
- 영상 해상도 입력 가능
- 프레임 입력 가능
- 생성 스텝 입력 가능
- 세로 대표 이미지는 영상 해상도를 자동으로 따라감
- 업로드 이미지가 있으면 바로 i2v, 없으면 바로 t2v
- 배너와 상세 이미지 번들을 먼저 만들지 않고 바로 영상 생성으로 들어감
- 품질 우선 기준으로 `24fps` 고정
- 긴 영상은 요청 크기(해상도 × fps × steps)에 따라 `2~5초` 단위 세그먼트로 분할 생성

### 음악 생성
- 업로드 없이 입력만으로 생성 가능
- 보컬 방식
  - `instrumental`
  - `vocal`
- 보컬일 때만
  - 가사 언어
  - 가사
- 보컬인데 가사가 비어 있으면 LLM이 가사를 생성
- LLM이 가사를 만들지 못하면 실패
- ACE-Step 추론은 별도 작업 프로세스에서 실행

## 3. 현재 출력
- 광고 문구 묶음
- 배너 이미지 3장
- 상세 이미지 2장
- 로고 초안 2장
- 원본 광고 영상 1개
- 배경 음악 1개
- 최종 합성 영상 1개

단, 영상 생성에서 음악을 끄면 음악과 최종 합성본은 만들지 않습니다.

## 4. 현재 고정 기술

### 서버와 화면
- 백엔드: `FastAPI`
- 프론트엔드: `Next.js`
- 연결: `Next.js app/api` 프록시
- 저장: `SQLite`

### 모델
- 문구/오케스트레이터: `gpt-5-mini`
- 이미지: `nunchaku-ai/nunchaku-z-image-turbo`
- 영상: `Wan-AI/Wan2.2-TI2V-5B-Diffusers`
- 음악: `ACE-Step/Ace-Step1.5`
- 합성: `ffmpeg`

## 6. 진입점 구조

### 메인 채팅
- 자연어 한 줄 요청만 받음
- 추가 입력 폼을 붙이지 않음
- LLM 에이전트가 요청을 읽고 실제 도구를 직접 호출
- 부족하면 `ask_for_more_info`
- 충분하면 `generate_image`, `generate_video`, `generate_music` 중 하나 호출
- 브라우저는 `/api/chat/generate`로 요청
- Next.js가 실제 `/chat/generate`로 프록시

### 전용 생성 화면
- `/image`
- `/video`
- `/music`

이 화면들은 공용 생성 도구를 더 정확하게 실행하기 위한 구조화 입력 화면입니다.
브라우저 요청은 각각:
- `/api/generate/image`
- `/api/generate/video`
- `/api/generate/music`

그리고 Next.js가 실제 FastAPI 주소로 전달합니다.

## 7. 현재 구현 상태

### 이미 구현된 것
- 채팅 기반 생성 요청
- 이미지 전용 생성 화면
- 영상 전용 생성 화면
- 음악 전용 생성 화면
- Next.js 프록시 라우트
- 공용 생성 도구 계층
- 실제 결과 파일 생성
- 업로드 파일 저장
- 조건부 음악 옵션 표시

### 현재 동작
- 이미지 생성과 영상 생성은 파일 업로드를 받음
- 음악 생성은 업로드 없이 동작
- 영상 생성은 음악을 아예 끌 수 있음
- 음악 생성과 영상 생성에서 보컬을 켜야만 가사 언어 / 가사 입력이 보임

## 8. 저장 기준
- 생성 결과 저장 위치:
  - `~/Downloads/장사한컷`
- 업로드 원본 임시 저장 위치:
  - `~/Downloads/uploads`

## 9. 실패 처리 원칙
- 모델 실패 시 폴백 결과물을 만들지 않습니다.
- 요청 해석은 규칙표가 아니라 LLM 도구 호출로 처리합니다.
- 영상 길이에 맞는 음악은 생성 단계에서 맞춰야 하며, 합성 단계에서 잘라 붙이지 않습니다.
- 길이가 맞지 않는 음악은 실패로 처리합니다.
- 이미지와 영상 파이프라인은 요청 종료 시점에 캐시를 해제합니다.
