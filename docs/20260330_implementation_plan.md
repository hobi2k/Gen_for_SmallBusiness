# 소상공인용 광고 콘텐츠 제작 플랫폼 구현 기획서

## 1. 프로젝트 목표
이 프로젝트는 소상공인이 상품 정보와 설명만 넣어도 광고에 바로 쓸 수 있는 결과물을 한 번에 만드는 서비스를 만드는 것이다. 사용자가 이미지를 함께 넣으면 그 이미지를 적극 반영하고, 이미지를 넣지 않아도 텍스트만으로 결과물을 만들 수 있게 한다. 결과물은 문구만이 아니라 배너 이미지, 상세 페이지 대표 이미지, 로고 초안, 짧은 광고 영상까지 포함한다.

핵심은 생성형 AI를 붙여 본 데모가 아니라, 실제 사용자가 결과물을 만들고 저장하고 다시 꺼내 쓸 수 있는 서비스로 완성하는 것이다. 그래서 이 프로젝트는 모델 하나에 모든 걸 맡기지 않고, 단계별 작업을 도구처럼 분리해 순서대로 실행하는 구조로 설계한다.

## 2. 우리가 만들 제품
제품 이름은 가칭으로 `장사한컷`으로 잡는다.

이 서비스는 아래 결과물을 고정으로 만든다.
- 광고 문구 세트
- 배너 이미지 세트
- 상세 페이지 상단 이미지 세트
- 로고 초안 세트
- 짧은 광고 영상 1개
- 배경 음악이 합쳐진 최종 mp4 1개

사용자는 긴 프롬프트를 직접 쓰지 않는다. 상품명, 설명, 분위기, 사진을 넣으면 된다. 서비스는 그 입력을 바탕으로 필요한 도구를 순서대로 호출해 결과물을 만든다.

## 3. 해결하려는 문제
소상공인은 광고 제작 과정에서 아래 문제를 반복해서 겪는다.
- 문구를 어떻게 써야 할지 막막하다.
- 배너와 상세 페이지 이미지를 직접 만들기 어렵다.
- 로고 초안조차 빠르게 보기 어렵다.
- 짧은 홍보 영상은 더 손이 많이 간다.
- 여러 생성 도구를 따로 써야 해서 결과물이 흩어진다.

이 서비스는 그 문제를 아래 방식으로 줄인다.
- 입력은 짧게 받고
- 생성은 자동으로 이어가고
- 결과물은 한 화면에 묶어 보여주고
- 다시 생성과 저장을 쉽게 한다.

## 4. 대상 사용자
대상 사용자는 아래로 고정한다.
- 온라인 판매를 시작했거나 운영 중인 소상공인
- 배너, 상세 페이지, SNS 홍보물을 직접 만들어야 하는 1인 운영자
- 디자이너 없이 빠르게 광고 소재를 만들어야 하는 사용자

초기 업종은 아래 두 가지로 제한한다.
- 식품
- 생활용품

이 두 업종은 상품 사진 중심 제작 수요가 높고, 배너와 상세 페이지 활용 빈도가 높아서 MVP 검증에 적합하다.

## 5. 서비스 원리
이 서비스는 하나의 모델이 모든 결과물을 한 번에 만드는 구조가 아니다. `도구 호출 방식`으로 동작한다.

오케스트레이터가 입력을 보고 어떤 작업을 어떤 순서로 실행할지 정한다. 실제 생성은 각 도구가 맡는다. 이렇게 해야 생성 실패를 단계별로 추적할 수 있고, 일부 결과만 다시 만드는 것도 가능해진다.

즉 이 프로젝트의 중심은 아래 두 가지다.
- 사용자에게는 한 번에 만드는 서비스처럼 보이게 할 것
- 내부에서는 단계별 도구 호출 구조로 안정적으로 운영할 것

## 6. 고정 사용자 흐름
이 프로젝트는 여러 시나리오를 두지 않는다. 아래 한 가지 흐름으로 고정한다.

1. 사용자가 업종, 상품명, 한 줄 소개, 상세 설명, 핵심 키워드, 분위기를 입력한다.
2. 사용자는 상품 사진을 넣을 수도 있고, 넣지 않을 수도 있다.
3. 사용자가 결과물 생성을 시작한다.
4. 오케스트레이터가 입력을 검사하고 누락값을 정리한다.
5. 문구 생성 도구를 호출한다.
6. 이미지 생성 도구를 호출해 배너, 상세 페이지 이미지, 로고 초안을 만든다.
7. 사용자가 이미지를 넣은 경우 대표 이미지를 선택한다.
8. 영상 생성 도구를 호출해 짧은 광고 영상을 만든다. 이미지를 넣었으면 이미지 기반으로, 없었으면 텍스트 기반으로 생성한다.
9. 음악 생성 도구를 호출해 배경 음악을 만든다.
10. 합성 도구를 호출해 최종 mp4를 만든다.
11. 저장 도구를 호출해 프로젝트 단위로 모든 결과물을 저장한다.
12. 사용자는 결과 화면에서 확인, 다운로드, 다시 생성을 진행한다.

## 7. 고정 입력값
입력 폼은 아래 필드로 고정한다.
- 업종
- 상품명
- 한 줄 소개
- 상세 설명
- 핵심 키워드 3개
- 강조할 판매 포인트
- 원하는 분위기
- 상품 사진 여러 장 또는 없음

분위기 선택도 아래 네 개로 고정한다.
- 깔끔한 판매형
- 따뜻한 공감형
- 밝은 행사형
- 고급스러운 브랜드형

## 8. 고정 출력값

### 8-1. 문구
- 메인 광고 문구 1개
- 보조 문구 2개
- 상세 페이지 상단 문구 1개
- SNS 짧은 문구 2개
- 영상용 짧은 카피 1개

### 8-2. 이미지
- 가로형 배너 3장
- 상세 페이지 상단 이미지 2장
- 정사각형 SNS 이미지 2장
- 로고 초안 2장

### 8-3. 영상
- 6초 광고 영상 1개
- 배경 음악이 합성된 최종 mp4 1개

## 9. 고정 모델과 기술 스택
선택지는 두지 않는다. 아래 구성을 기준으로 구현한다.

### 9-1. 오케스트레이터
- 모델: `gpt-5-mini`
- 역할: 입력 정리, 단계 판단, 도구 호출 순서 결정, 실패 시 재시도 분기 처리

### 9-2. 문구 생성
- 모델: `gpt-5-mini`
- 역할: 광고 문구, 상세 페이지 상단 문구, 짧은 영상용 카피 생성

### 9-3. 이미지 생성
- 기본 모델: `FLUX.1-dev`
- 보조 기법: `IP-Adapter`
- 역할: 상품 사진이 있으면 반영하고, 없으면 텍스트만으로 배너, 상세 페이지 대표 이미지, SNS 이미지 생성

### 9-4. 로고 초안 생성
- 모델: `FLUX.1-dev`
- 역할: 업종과 분위기에 맞는 로고 초안 생성

### 9-5. 영상 생성
- 모델: `Wan2.2-TI2V-5B`
- 역할: 이미지가 있으면 이미지 기반, 없으면 텍스트 기반으로 6초 광고 영상 생성

### 9-6. 음악 생성
- 모델: `ACE-Step 1.5`
- 역할: 분위기에 맞는 6초 배경 음악 생성

### 9-7. 최종 합성
- 도구: `ffmpeg`
- 역할: 영상과 음악을 합쳐 최종 mp4 생성

### 9-8. 프론트엔드
- `Next.js`
- `TypeScript`
- `Tailwind CSS`
- `shadcn/ui`

### 9-9. 백엔드
- `FastAPI`
- `Pydantic`
- `SQLAlchemy`

### 9-10. 데이터 저장
- `SQLite`

### 9-11. 파일 저장
- 로컬 스토리지 기반 `storage/` 디렉토리

### 9-12. 실행 환경
- `GCP VM + L4 GPU`

## 10. 도구 목록
이 서비스는 아래 도구를 고정으로 사용한다.

### 10-1. `validate_input`
- 입력값 누락 여부 확인
- 업로드 이미지 존재 여부와 사용자가 넣은 개수 확인
- 기본 필드 정리

### 10-2. `generate_copy`
- 메인 문구 생성
- 보조 문구 생성
- 상세 페이지 상단 문구 생성
- 영상용 짧은 카피 생성

### 10-3. `generate_banner_images`
- 배너 3장 생성

### 10-4. `generate_detail_images`
- 상세 페이지 상단 이미지 2장 생성
- SNS 이미지 2장 생성

### 10-5. `generate_logo_drafts`
- 로고 초안 2장 생성

### 10-6. `select_key_visual`
- 사용자가 이미지를 넣은 경우 영상 생성에 쓸 대표 이미지 1장 선택

### 10-7. `generate_short_video`
- `Wan2.2-TI2V-5B`로 6초 광고 영상 생성
- 이미지가 있으면 이미지 기반 생성
- 이미지가 없으면 텍스트 기반 생성

### 10-8. `generate_music`
- `ACE-Step 1.5`로 6초 배경 음악 생성

### 10-9. `compose_final_video`
- `ffmpeg`로 영상과 음악 합성

### 10-10. `save_project_assets`
- 모든 결과물을 프로젝트 단위로 저장
- DB 메타데이터 기록

## 12. 시스템 구조
구조는 아래 흐름으로 고정한다.

1. Next.js 화면에서 입력을 받는다.
2. FastAPI가 프로젝트를 생성한다.
3. 오케스트레이터가 `validate_input`을 호출한다.
4. 오케스트레이터가 `generate_copy`를 호출한다.
5. 오케스트레이터가 `generate_banner_images`, `generate_detail_images`, `generate_logo_drafts`를 차례로 호출한다.
6. 이미지가 있으면 오케스트레이터가 `select_key_visual`을 호출한다.
7. 오케스트레이터가 `generate_short_video`를 호출한다.
8. 오케스트레이터가 `generate_music`를 호출한다.
9. 오케스트레이터가 `compose_final_video`를 호출한다.
10. 오케스트레이터가 `save_project_assets`를 호출한다.
11. 프론트엔드가 결과를 한 화면에 묶어 보여준다.

## 13. 기능별 구현 계획

### 13-1. 입력 검사
입력 단계에서는 사용자가 길고 복잡한 설명을 쓰지 않아도 되게 한다. 업종, 상품명, 핵심 설명, 분위기만 있으면 생성이 가능해야 한다. 이미지는 있어도 되고 없어도 된다. 누락값은 오케스트레이터가 검사하고, 부족한 항목은 기본값 규칙으로 정리한다.

### 13-2. 문구 생성
문구는 짧고 바로 써먹을 수 있어야 한다. 설명문보다 판매 포인트가 먼저 읽히는 문장으로 고정한다. 결과는 배너, 상세 페이지, SNS, 영상에서 바로 재사용할 수 있게 형식을 분리해 저장한다.

### 13-3. 배너 이미지 생성
배너는 시선을 잡는 결과물이 나와야 한다. 상품 사진이 있으면 FLUX.1-dev와 IP-Adapter를 함께 써서 상품 형태를 반영하고, 사진이 없으면 텍스트를 바탕으로 구도와 분위기를 만든다.

### 13-4. 상세 페이지 이미지 생성
상세 페이지 이미지는 전체 문서를 자동 작성하는 기능이 아니다. 상단에서 시선을 잡는 대표 이미지와 보조 이미지를 만드는 기능으로 제한한다. 제품 사진이 있으면 그 이미지를 우선 활용하고, 없으면 상품 설명을 바탕으로 생성한다.

### 13-5. 로고 초안 생성
로고는 최종 납품물이 아니라 브랜드 방향을 빠르게 보기 위한 초안 기능이다. 심볼형과 텍스트형 두 가지 결과를 만들어 사용자가 바로 참고할 수 있게 한다.

### 13-6. 광고 영상 생성
영상은 6초 길이로 고정한다. 사용자가 이미지를 넣은 경우에는 대표 이미지를 뽑아 `Wan2.2-TI2V-5B`의 이미지 기반 생성으로 진행하고, 이미지를 넣지 않은 경우에는 텍스트 기반 생성으로 진행한다. 영상은 이미지 슬라이드가 아니라 실제 움직임이 있는 짧은 광고 컷으로 만든다.

### 13-7. 음악 생성과 합성
광고 영상은 무음으로 끝내지 않는다. 분위기 선택값을 바탕으로 `ACE-Step 1.5`로 6초 음악을 만들고, `ffmpeg`로 영상과 합친다. 최종 결과물은 바로 공유 가능한 mp4로 저장한다.

### 13-8. 결과 보관
결과물은 프로젝트 단위로 저장한다. 사용자는 지난 생성 결과를 다시 열어보고, 일부 결과를 다시 만들거나 전체를 다시 생성할 수 있다.

## 14. 저장 구조
프로젝트 저장 구조는 아래처럼 고정한다.

```text
storage/
  projects/
    {project_id}/
      input.json
      copy.json
      banner_1.png
      banner_2.png
      banner_3.png
      detail_1.png
      detail_2.png
      square_1.png
      square_2.png
      logo_1.png
      logo_2.png
      key_visual.png
      video_raw.mp4
      music.mp3
      final_ad.mp4
```

SQLite에는 아래 정보를 저장한다.
- project_id
- 상품명
- 업종
- 분위기
- 생성 시각
- 생성 상태
- 대표 결과물 경로
- 오류 메시지
- 마지막으로 실패한 도구 이름

## 17. 성공 기준
이 프로젝트는 아래 기준을 만족해야 한다.
- 사용자가 5분 안에 결과물을 만들 수 있다.
- 문구, 이미지, 영상이 한 프로젝트 안에서 함께 저장된다.
- 배너와 상세 페이지 이미지가 실제 판매 화면에 바로 붙일 수 있을 정도로 정리되어 나온다.
- 최종 광고 영상은 음악까지 포함된 mp4로 내려받을 수 있다.
- 생성 실패 시 어느 도구 단계에서 실패했는지 확인할 수 있다.

## 18. 발표에서 강조할 포인트
발표에서는 아래를 강조한다.
- 상품 정보와 설명만으로 실제 광고 결과물을 한 번에 만들 수 있다는 점
- 이미지가 있으면 반영하고, 이미지가 없어도 텍스트만으로 결과물을 만들 수 있다는 점
- 이미지 생성에서 끝나지 않고 짧은 광고 영상과 음악 합성까지 이어진다는 점
- 하나의 모델에 맡긴 것이 아니라 도구 호출 구조로 안정성과 재시도 흐름을 잡았다는 점
- 생성형 AI 실험이 아니라 실제 서비스 흐름을 갖춘 제품이라는 점

## 19. 주요 리스크와 대응

### 19-1. 영상 생성 시간이 길어질 수 있음
대응:
- 영상 길이를 6초로 고정한다.
- 이미지가 있으면 대표 이미지 1장만 써서 입력을 단순화한다.

### 19-2. 이미지 품질 편차가 클 수 있음
대응:
- 초기 업종을 식품과 생활용품으로 제한한다.
- 분위기 선택지를 4개로 고정한다.

### 19-3. 결과물 톤이 서로 어긋날 수 있음
대응:
- 모든 도구에서 같은 분위기 값을 공통으로 사용한다.
- 문구 생성 결과를 이미지와 영상 생성 입력에 함께 사용한다.

### 19-4. 일부 도구만 실패할 수 있음
대응:
- 도구 단위 상태값을 저장한다.
- 실패한 도구만 다시 실행할 수 있게 한다.

## 20. 결론
이 프로젝트는 소상공인이 짧은 입력만으로 광고 문구, 배너 이미지, 상세 페이지 대표 이미지, 로고 초안, 짧은 광고 영상까지 한 번에 만들 수 있는 광고 제작 플랫폼을 목표로 한다. 구현 방식은 도구 호출 구조로 고정하고, 오케스트레이터는 `gpt-5-mini`, 이미지 생성은 `FLUX.1-dev`, 영상 생성은 `Wan2.2-TI2V-5B`, 음악 생성은 `ACE-Step 1.5`, 최종 합성은 `ffmpeg`로 고정해 바로 구현에 들어간다.

이 문서는 아이디어 메모가 아니라 실제 구현 기준 문서로 사용한다. 이후 작업은 이 문서를 기준으로 화면 설계, API 설계, 도구 명세, 작업 분해 문서로 이어간다.
