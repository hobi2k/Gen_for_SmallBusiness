### 1. 톤(Tone) 이름 불일치 — 폴백 이미지/음악 색상·주파수가 항상 기본값으로 생성됨

**위치**
- `backend/app/tools/validation_tool.py` — `ALLOWED_TONES`
- `backend/app/tools/runtime_support.py` — `pick_tone_colors()` 팔레트
- `backend/app/tools/music_tool.py` — `_pick_frequency()` 테이블

**내용**

`validation_tool.py`의 허용 톤 집합과, 실제 색상/주파수를 결정하는 함수의 딕셔너리 키가 서로 다릅니다.

```python
# validation_tool.py (검증에서 실제 통과되는 값)
ALLOWED_TONES = {
    "깔끔한 판매형",
    "따뜻한 공감형",     # ← 실제 통과 값
    "밝은 행사형",       # ← 실제 통과 값
    "고급스러운 브랜드형", # ← 실제 통과 값
}

# runtime_support.py pick_tone_colors (팔레트 키)
palette = {
    "깔끔한 판매형": ...,
    "신뢰감 있는 설명형": ...,  # ← ALLOWED_TONES에 없음
    "감성 공감형": ...,         # ← ALLOWED_TONES에 없음
    "밝은 행사 홍보형": ...,    # ← ALLOWED_TONES에 없음
}

# music_tool.py _pick_frequency (주파수 테이블 키)
table = {
    "깔끔한 판매형": 392,
    "신뢰감 있는 설명형": 330,  # ← ALLOWED_TONES에 없음
    "감성 공감형": 262,          # ← ALLOWED_TONES에 없음
    "밝은 행사 홍보형": 523,    # ← ALLOWED_TONES에 없음
}
```

**결과** 사용자가 "따뜻한 공감형", "밝은 행사형", "고급스러운 브랜드형" 중 하나를 선택하면:
- `pick_tone_colors`는 항상 기본 회색 `((238, 238, 238), (148, 148, 148))`을 반환
- `_pick_frequency`는 항상 기본 주파수 `392`를 반환
- 4개 톤 중 "깔끔한 판매형"만 정상 동작하고, 나머지 3개는 스타일 없는 기본 결과가 생성됨

**수정 방향** `pick_tone_colors`와 `_pick_frequency`의 키를 `ALLOWED_TONES` 기준으로 통일합니다.

### 2. ACE-Step 체크포인트 경로 불일치 — GPU 환경에서 `FileNotFoundError`

**위치** `backend/app/tools/music_tool.py` — `_find_ace_step_checkpoint_dir()`

**내용**

`model_manifest.json`의 `repo_id`는 `"ACE-Step/Ace-Step1.5"`입니다.
HuggingFace `snapshot_download`로 내려받으면 로컬 캐시 폴더 이름은 `models--ACE-Step--Ace-Step1.5`가 됩니다.

그런데 코드는 다른 이름을 검색합니다.

```python
# music_tool.py:31
snapshot_candidates = sorted(
    model_dir.glob("models--ACE-Step--ACE-Step-v1-3.5B/snapshots/*"),  # ← 이름 다름
)
```

- 실제 glob 대상: `models--ACE-Step--Ace-Step1.5/snapshots/*`
- 코드가 찾는 패턴: `models--ACE-Step--ACE-Step-v1-3.5B/snapshots/*`

**결과** 실제 GPU 환경에서 모델을 다운로드해도 스냅샷을 찾지 못하고 `FileNotFoundError`가 발생합니다.

**수정 방향** glob 패턴을 `"models--ACE-Step--Ace-Step1.5/snapshots/*"`로 수정하거나, 매니페스트에서 `repo_id`를 파싱해 동적으로 경로를 구성합니다.

### 3. `pyproject.toml` — 존재하지 않는 PyTorch 버전

**위치** `pyproject.toml` — `[project.optional-dependencies] ai`

**내용**

```toml
"torch==2.10.*",
"torchvision==0.25.*",
"torchaudio==2.10.*",
```

PyTorch 2.10은 출시되지 않은 버전입니다(2026-04-01 기준). `uv pip install -e ".[ai]"` 실행 시 패키지를 찾지 못해 설치가 즉시 실패합니다.

**수정 방향** 실제 설치 가능한 최신 안정 버전으로 교체합니다. (예: `torch>=2.6.0,<2.7.0`)

### 4. CORS 설정 — wildcard + credentials 동시 사용

**위치** `backend/app/main.py`

**내용**

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],       # ← wildcard
    allow_credentials=True,    # ← credentials 동시 허용
    ...
)
```

CORS 스펙상 `Allow-Origin: *`와 `credentials: include`는 동시에 허용되지 않습니다.
브라우저는 이 조합을 만나면 요청을 차단합니다.
현재 Next.js 서버 사이드 프록시 방식에서는 직접 영향이 없지만, 클라이언트에서 직접 백엔드를 호출하는 경우 또는 프록시 없이 테스트할 때 CORS 오류가 발생합니다.

**수정 방향** `allow_origins`를 실제 허용 Origin 목록으로 구체화하거나, `allow_credentials=False`로 설정합니다.

### 5. 영상 생성 화면에서 음악 기본값이 꺼짐 (`generation-form.tsx`)

**위치** `frontend/components/generation-form.tsx:53`

**내용**

```tsx
const [includeMusic, setIncludeMusic] = useState(mode !== 'video');
```

`mode === 'video'`일 때 `includeMusic = false`로 초기화됩니다.
`ProjectCreateRequest`의 `include_music` 스키마 기본값은 `True`이고, 문서(`architecture.md`, `20260330_implementation_plan.md`)에서도 "음악을 끌 수 있음"으로 기술되어 있어, **기본은 켜져 있어야** 함을 암시합니다.

**결과** 사용자가 체크박스를 수동으로 켜야만 음악이 생성됩니다. 의도적으로 끄고 싶은 경우에만 체크 해제하는 방향이 더 자연스럽습니다.

**수정 방향**

```tsx
const [includeMusic, setIncludeMusic] = useState(true);
```

### 6. `orchestrator.py` — `include_music` 플래그 무시

**위치** `backend/app/services/orchestrator.py:60-62`

**내용**

```python
video_path = generate_short_video(...)
music_path = generate_music(...)           # ← include_music 확인 없음
final_video_path = compose_final_video(...)  # ← include_music 확인 없음
```

오케스트레이터는 `validated_payload.include_music` 값에 관계없이 음악과 합성을 항상 실행합니다.
반면 `generation_service.py::generate_video_asset_bundle`은 올바르게 분기합니다.

```python
# generation_service.py (올바른 구현)
if request.include_music:
    music_path = generate_music(...)
    final_video_path = compose_final_video(...)
```

**결과** Projects API 경로(`/api/projects`)를 통해 생성 요청을 보낼 때 `include_music=false`를 설정해도 음악과 합성 단계가 실행됩니다. 불필요한 처리가 발생하고 사용자 의도가 무시됩니다.

**수정 방향** 오케스트레이터에 `include_music` 조건 분기를 추가합니다.

### 8. `generation.py` — `File(default_factory=list)` 잘못된 파라미터

**위치** `backend/app/api/generation.py:53`

**내용**

```python
images: list[UploadFile] = File(default_factory=list),
```

FastAPI의 `File()`은 `default_factory` 인자를 지원하지 않습니다.
현재는 런타임에서 이 인자가 무시될 수 있지만, FastAPI/Pydantic 버전에 따라 예외가 발생하거나 파라미터 처리가 달라질 수 있습니다.

**수정 방향**

```python
images: list[UploadFile] = File(default=[]),
```

### 14. `image_tool.py` — text/img2img 파이프라인이 각각 별도 Transformer 로드

**위치** `backend/app/tools/image_tool.py:188-261`

**내용**

`_get_nunchaku_text_pipeline()`과 `_get_nunchaku_img2img_pipeline()`은 각각 `lru_cache`로 캐시되지만, 두 함수 모두 독립적으로 `NunchakuZImageTransformer2DModel.from_pretrained()`를 호출합니다.

같은 세션에서 text-to-image와 image-to-image가 모두 호출되면 동일한 transformer 가중치가 VRAM에 두 번 올라갑니다.

**수정 방향** transformer 로드를 별도 `lru_cache` 함수로 분리하고, 두 파이프라인이 같은 transformer 인스턴스를 공유하도록 변경합니다.

### 15. `scripts/initialize_models.py` — `local_dir_use_symlinks` deprecated 파라미터

**위치** `scripts/initialize_models.py:108`

**내용**

```python
snapshot_download(
    repo_id=model["repo_id"],
    local_dir=target_dir,
    local_dir_use_symlinks=False,  # ← huggingface_hub 최신 버전에서 deprecated
    resume_download=True,
)
```

`huggingface_hub>=0.23.0`부터 `local_dir_use_symlinks`는 deprecated입니다. 최신 버전에서는 경고 또는 오류가 발생할 수 있습니다.

**수정 방향** `local_dir_use_symlinks=False` 줄을 제거합니다. 최신 `huggingface_hub`는 기본적으로 심볼릭 링크를 사용하지 않습니다.
