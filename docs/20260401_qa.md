### 4. CORS 설정 — wildcard + credentials 동시 사용

**위치** `backend/app/main.py`

**내용**

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],       # ← wildcard
    allow_credentials=True,    # ← credentials 동시 허용
    ...
)
```

CORS 스펙상 `Allow-Origin: *`와 `credentials: include`는 동시에 허용되지 않습니다.
브라우저는 이 조합을 만나면 요청을 차단합니다.
현재 Next.js 서버 사이드 프록시 방식에서는 직접 영향이 없지만, 클라이언트에서 직접 백엔드를 호출하는 경우 또는 프록시 없이 테스트할 때 CORS 오류가 발생합니다.

**수정 방향** `allow_origins`를 실제 허용 Origin 목록으로 구체화하거나, `allow_credentials=False`로 설정합니다.

**수정 방향**

```tsx
const [includeMusic, setIncludeMusic] = useState(true);
```

2. 영상 단계: `_get_wan_t2v_pipeline()` / `_get_wan_i2v_pipeline()` → 이미지 모델이 캐시에 남은 채로 추가 로드
3. 음악 단계: `_get_ace_step_pipeline()` → 이미지+영상 모델이 캐시에 남은 채로 추가 로드

모든 파이프라인이 `lru_cache`로 고정되며, 어디서도 `.cache_clear()` / `torch.cuda.empty_cache()`가 호출되지 않아 세 모델이 동시에 RAM/VRAM에 올라갑니다. OOM으로 프로세스가 종료되면 HTTP 응답이 없고, 프론트엔드에서 `Unexpected end of JSON input` 오류가 발생합니다.

**수정 내용**

- `image_tool.py`에 `release_image_pipelines()` 추가 — lru_cache 클리어 + `torch.cuda.empty_cache()`
- `video_tool.py`에 `release_video_pipelines()` 추가 — 동일
- `generation_service.py::generate_video_asset_bundle`에서:
  - 이미지 생성 완료 후 → `release_image_pipelines()` 호출
  - 영상 생성 완료 후 (음악 포함 시) → `release_video_pipelines()` 호출

**→ 해결됨**
