# 글자 오버레이 구현 계획

## 1. 목표

이미지 생성 모델과 영상 생성 모델이 한글을 직접 쓰게 두지 않는다.  
비주얼은 모델이 만들고, 글자는 후처리 단계에서 정확하게 얹는다.

이 문서의 목표는 다음 두 가지다.

1. 배너와 상세 이미지에 한글 카피를 정확하게 얹는다.
2. 광고 영상에 한글 문구를 정확하게 얹는다.

즉 모델은 배경, 제품, 분위기만 만들고, 실제 광고 문구는 코드로 합성한다.

## 2. 왜 이렇게 가는가

현재 이미지 모델과 영상 모델은 한글 글자를 안정적으로 만들지 못한다.

대표 문제:
- 글자 깨짐
- 철자 틀림
- 간격 붕괴
- 읽을 수 없는 한글 비슷한 형태

그래서 이 프로젝트에서는 아래 원칙을 고정한다.

- 모델은 제품, 배경, 영어 라벨처럼 상대적으로 안정적인 비주얼 생성만 담당
- 광고 문구는 후처리 오버레이로만 넣음
- 글자 정확도는 모델이 아니라 코드에서 보장
- 영어 라벨은 생성 모델이 만들 수 있게 열어두고, 한국어 카피는 후처리에서만 넣음

현재 이미지 생성 기준:
- 업로드 이미지가 있으면 광고 포스터형 `img2img`
- 업로드 이미지가 없으면 광고 포스터형 `text-to-image`
- 한국어 자체를 프롬프트에서 금지하지 않음
- 다만 한국어 카피 정확도는 여전히 후처리 오버레이로 보장

## 3. 구현 원칙

### 3-1. 절대 원칙
- 생성 모델에게 한글 문장을 직접 쓰게 하지 않는다.
- 결과물이 마음에 안 들어도 글자 문제를 모델 프롬프트로 해결하려 하지 않는다.
- 텍스트 정확도는 후처리 단계에서만 해결한다.

### 3-2. 데이터 원칙
- 오버레이에 쓰는 문구는 [backend/app/tools/copy_tool.py](../backend/app/tools/copy_tool.py) 또는 LLM 카피 생성 결과를 사용한다.
- 이미 생성된 `headline`, `subheads`, `detail_headline`, `short_social_copies`를 재활용한다.
- 이미지용 문구와 영상용 문구는 같은 카피 묶음에서 가져오되, 배치 방식만 다르게 한다.

## 4. 이미지 오버레이 계획

### 4-1. 도구
- `PIL.Image`
- `PIL.ImageDraw`
- `PIL.ImageFont`

### 4-2. 적용 대상
- `banner_*.png`
- `detail_*.png`
- 필요하면 `logo_*.png`는 제외 또는 최소 적용

### 4-3. 오버레이 구성

배너 기준:
- 상단 또는 좌측 큰 제목
- 그 아래 한 줄 보조 문구
- 우하단 또는 하단 CTA 박스

상세 이미지 기준:
- 큰 제목
- 보조 문구 1~2줄
- 판매 포인트 1~2개

### 4-4. 배치 원칙
- 텍스트는 이미지 가장자리와 충분한 여백을 둔다.
- 제목은 2줄을 넘기지 않는다.
- 배경 대비가 약하면 반투명 박스 또는 그림자를 둔다.
- 긴 문장은 자동 줄바꿈한다.
- 텍스트 안전영역을 미리 정하고 그 안에만 배치한다.

### 4-5. 필요한 구현 함수
- `load_overlay_font()`
- `wrap_korean_text()`
- `draw_headline_block()`
- `draw_subhead_block()`
- `draw_cta_badge()`
- `overlay_text_on_image()`

### 4-6. 출력 방식
- 원본 생성 이미지 보존
- 텍스트가 올라간 최종본을 별도 파일로 저장

예:
- `banner_1.png` 원본
- `banner_1_overlay.png` 최종본

또는 실제 서비스 표시용으로는:
- `banner_1.png`를 최종본으로 교체하고
- 원본은 `banner_1_raw.png`로 남기는 방식도 가능

현재 프로젝트 기준으로는 원본과 최종본을 모두 남기는 쪽이 안전하다.

## 5. 영상 오버레이 계획

### 5-1. 도구
- `PIL`로 만드는 투명 오버레이 PNG
- `ffmpeg overlay`

### 5-2. 적용 대상
- `video_raw.mp4`
- 최종 출력 `final_ad.mp4`

### 5-3. 오버레이 구성

영상 기본안:
- 오프닝 0.0s ~ 1.8s: 큰 제목
- 본문 1.8s ~ 4.8s: 보조 문구 또는 판매 포인트
- 엔딩 4.8s ~ 끝: 짧은 CTA 또는 제품명

### 5-4. 배치 원칙
- 텍스트는 화면 중앙 정렬보다 좌하단 또는 좌중단 중심이 안정적이다.
- 영상 내용 가림을 줄이기 위해 고정된 안전영역을 사용한다.
- 반투명 박스 또는 그림자를 반드시 둔다.
- 한 장면에 문장 하나만 보여준다.
- 텍스트가 길면 한 줄이 아니라 두 줄로 나눈다.

### 5-5. 필요한 구현 함수
- `build_overlay_layer()`
- `overlay_text_on_video()`
- `compose_video_with_music_and_text()`

### 5-6. 시간축 설계
- 영상 길이는 현재 `1~40초`
- 길이에 맞춰 문구 수를 자동 조절

예:
- 3~4초: 제목 + CTA
- 5~7초: 제목 + 보조 문구 + CTA
- 8~10초: 제목 + 보조 문구 + 판매 포인트 + CTA

## 6. 폰트 계획

### 6-1. 요구사항
- 한글이 확실히 지원되어야 한다.
- 서버 환경에서 경로가 안정적이어야 한다.
- 이미지와 영상에서 같은 계열 폰트를 써야 한다.

### 6-2. 추천
- `Noto Sans KR`
- 필요하면 굵기별 파일 같이 저장

### 6-3. 배치 방식
- 프로젝트 내부 `assets/fonts/` 폴더 생성
- 예:
  - `assets/fonts/NotoSansKR-Regular.ttf`
  - `assets/fonts/NotoSansKR-Bold.ttf`

이 경로를 `PIL`과 영상 오버레이 합성 단계에서 공통 사용한다.

## 7. 현재 코드에 붙일 위치

### 이미지
- 현재 생성: [backend/app/tools/image_tool.py](../backend/app/tools/image_tool.py)
- 추가 예정:
  - `text_overlay_tool.py` 신설
  - 또는 `image_tool.py` 내부 후처리 함수 추가

추천:
- 오버레이 로직은 별도 파일 `text_overlay_tool.py` 로 분리

### 영상
- 현재 생성: [backend/app/tools/video_tool.py](../backend/app/tools/video_tool.py)
- 현재 합성: [backend/app/tools/composition_tool.py](../backend/app/tools/composition_tool.py)

현재 구조:
- 영상 텍스트 오버레이는 [backend/app/tools/text_overlay_tool.py](../backend/app/tools/text_overlay_tool.py) 에서 만든다.
- 합성은 [backend/app/tools/composition_tool.py](../backend/app/tools/composition_tool.py) 에서 맡는다.
- 흐름은 `video_raw.mp4 -> video_overlay.mp4 -> final_ad.mp4` 이다.
- 영상 생성은 품질 우선 `24fps` 기준으로 돌고, 긴 영상은 `5초` 단위 세그먼트로 분할 생성한다.

## 8. 파일 구조 제안

추천 추가 파일:
- `backend/app/tools/text_overlay_tool.py`

이 파일 역할:
- 한글 줄바꿈
- 폰트 로딩
- 이미지 텍스트 합성
- 영상 오버레이 PNG 생성과 합성

## 9. 단계별 구현 순서

### 1단계
- 폰트 파일 준비
- `assets/fonts/` 경로 확정
- `text_overlay_tool.py` 생성

### 2단계
- 이미지 오버레이 함수 구현
- 배너 이미지 1장 기준으로 먼저 적용
- 실제 생성 결과 확인

### 3단계
- 상세 이미지 오버레이 적용
- 줄바꿈, 그림자, 박스 스타일 조정

### 4단계
- 영상 오버레이 PNG 합성 구현
- `video_raw.mp4` 위에 제목 1개만 먼저 얹기

### 5단계
- 길이별 텍스트 타임라인 적용
- CTA까지 포함한 최종 `final_ad.mp4` 생성

### 6단계
- 채팅 결과 미리보기에는 텍스트 오버레이가 적용된 최종 파일만 노출
- 다운로드도 최종 파일 기준으로 제공

## 10. 검증 계획

### 이미지 검증
- 제목이 잘리지 않는가
- 한글이 깨지지 않는가
- 문구 대비가 충분한가
- 배경 위에서 읽히는가

### 영상 검증
- 텍스트가 너무 빨리 사라지지 않는가
- 문구가 영상 내용을 가리지 않는가
- 한글이 정확하게 렌더되는가
- 음악과 함께 최종본 길이가 맞는가

### 공통 검증
- 다운로드 파일이 최종본인가
- 원본 생성물과 최종본이 구분되는가
- 폰트 경로가 환경마다 안정적인가

## 11. 최종 목표 상태

최종적으로 사용자가 받게 되는 것은 이것이다.

이미지:
- 모델이 만든 원본 비주얼
- 한글 카피가 정확히 올라간 최종 배너/상세 이미지

영상:
- 모델이 만든 글자 없는 원본 영상
- 한글 카피와 음악이 합쳐진 최종 광고 영상

즉 "모델이 글자를 잘 쓰길 기대하는 구조"가 아니라,
"모델은 비주얼, 코드는 글자" 구조로 고정한다.
